# PDF privados de cotizaciones en Cloudflare R2

Las nuevas cargas usan R2 cuando están presentes las cuatro variables; en caso contrario siguen usando Blob si tiene su token configurado. Cada documento conserva su proveedor. Los archivos existentes en Blob no se trasladan ni se borran: conservar BLOB_READ_WRITE_TOKEN para consultarlos.

## Configuración

1. Crear un bucket privado en Cloudflare R2. Mantener desactivados el acceso r2.dev y los dominios públicos.
2. Crear una credencial R2 con permisos de lectura/escritura únicamente para ese bucket.
3. Añadir en las variables del proyecto Vercel (no en Git ni en chat):
   - R2_ENDPOINT: endpoint S3 HTTPS mostrado por Cloudflare, sin ruta de bucket.
   - R2_BUCKET: nombre del bucket.
   - R2_ACCESS_KEY_ID: identificador de acceso.
   - R2_SECRET_ACCESS_KEY: clave secreta.
4. Usar buckets y credenciales distintos para Preview y Production.
5. Configurar CORS en el bucket para el origen exacto de la aplicación. Ejemplo para producción:

```json
[
  {
    "AllowedOrigins": ["https://consitec-nu.vercel.app"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["Content-Type", "If-None-Match"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

Añadir el origen exacto de la preview a su bucket de pruebas. No usar `*` para los orígenes. CORS no hace público el bucket.

6. Aplicar la migración `20261012050000_quotation_storage_provider` con `npm run prisma:deploy` y volver a desplegar.

## Flujo

La aplicación autoriza al propietario/administrador y reserva el documento. La subida se hace directamente desde el navegador a R2 mediante una URL firmada de tres minutos, con tamaño y tipo PDF firmados y `If-None-Match: *` para impedir sobrescrituras. Esto evita el límite de tamaño de las funciones de Vercel. Se mantiene el máximo de 25 MB.

Antes de publicar el documento, el servidor comprueba tamaño, tipo y cabecera `%PDF-`. Las rutas de CONSITEC verifican el permiso y redirigen a un enlace firmado de R2 válido durante 60 segundos. El navegador abre o descarga el PDF directamente, evitando transferir el archivo por Vercel. El enlace puede reutilizarse y compartirse mientras está vigente; el bucket permanece privado. Los documentos antiguos de Blob conservan la descarga autenticada a través de la aplicación. Las descargas de R2 son navegaciones, por lo que no requieren agregar GET a la política CORS de la subida. El mantenimiento elimina las cargas abandonadas según el proveedor de cada documento.

## Validación

`node scripts/quotation-storage-check.mjs` comprueba la firma y el adaptador con transporte SDK simulado; no sustituye una prueba en R2.

Con un bucket privado de pruebas: subir un PDF, abrirlo, descargarlo y comparar el archivo; verificar que otra cuenta comercial y un usuario sin sesión no puedan leerlo. Verificar la negativa de carga al cambiar el tamaño, tipo o intentar sobrescribir el objeto. Comprobar el acceso a los documentos antiguos en Blob si existen.

Hasta configurar las credenciales y CORS y superar estas comprobaciones, no considerar R2 operativo. La migración no mueve archivos existentes.
